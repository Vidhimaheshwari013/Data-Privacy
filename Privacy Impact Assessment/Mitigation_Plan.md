# Mitigation Plan

## 1. Data Security

- Encrypt biometric and attendance data.
- Use strong authentication.
- Implement role-based access control.
- Maintain access logs.
- Secure the database.

## 2. Recognition Accuracy

- Test the facial recognition system before deployment.
- Allow manual attendance verification.
- Provide a correction mechanism.
- Monitor false matches.
- Provide an alternative attendance method.

## 3. Purpose Limitation

Biometric information should only be used for attendance.

The institution should not use the collected information for unrelated surveillance, profiling or other purposes.

Any change in purpose should require a new privacy assessment.

## 4. Data Retention

- Define a retention period.
- Delete biometric information when it is no longer required.
- Securely delete old records.
- Periodically review stored information.

## 5. Transparency

Students should be informed about:

- What data is collected.
- Why it is collected.
- How it is used.
- How long it is stored.
- Who can access it.
- How to request correction or raise concerns.

## 6. Access Control

### Student
Can view their own attendance.

### Teacher
Can manage attendance for assigned classes.

### Administrator
Can manage the system.

### IT/Security Staff
Can access technical information only when necessary.

## 7. Third-Party Vendors

If an external vendor operates the system:

- Limit vendor access.
- Include privacy and security requirements in contracts.
- Prevent unrelated use of student data.
- Require secure deletion or return of data when the service ends.

## 8. Privacy-by-Design

The system should:

1. Collect minimum necessary information.
2. Protect biometric templates.
3. Encrypt sensitive information.
4. Use role-based access.
5. Maintain audit logs.
6. Apply automatic retention rules.
7. Provide clear privacy notices.
8. Provide a correction mechanism.
9. Regularly test security and accuracy.
10. Reassess privacy risks when the system changes.
